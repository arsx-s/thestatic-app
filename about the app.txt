Encryption
This needs to be genuine end-to-end encryption, not simply a password-protected database.

For private conversations:
- Encryption happens on the sender's device.
- Decryption happens on the recipient's device.
- The server stores ciphertext.
- The server cannot read the message contents.
- Each conversation has cryptographic identity keys.
- Support secure device changes and key verification.

Membership process
1. Someone visits The Static website.
2. They apply to become a Static.
3. The team reviews their application.
4. If approved, an administrator creates their account.
5. The member receives their Static ID and an invitation.
6. They install the app.
7. They log in.
There should be no public account creation endpoint.
Password security
One important technical correction: passwords should not be reversibly encrypted.

They should be securely hashed using a modern password-hashing algorithm such as Argon2id.

You should also consider:
- Rate-limited login attempts.
- Secure password recovery.
- Optional passkeys.
- Two-factor authentication.
- Device/session management.
- Secure storage of cryptographic keys on the device.
And don't forget: E2EE introduces a recovery problem. If someone loses their phone and their encryption keys, recovering their account should not automatically mean the server can decrypt their old conversations.

A recovery key or secure device-transfer system will be necessary.
4. The privacy question — no data collection
I love the intention, but we need to distinguish between two things.

No unnecessary data collection and no data existing on the server are not the same.

Your app needs to store certain information to function.
Information	Does the system need it?
Static ID	Yes
Username	Yes
Password hash	Yes
Posts	Yes
Profile information	Yes
Following relationships	Yes
Marketplace listings	Yes
Private message contents	No readable server copy
Advertising profiles	No
Third-party tracking	No
Behavioural analytics	No
AI recommendation profiling	No

Here's the architecture I'd aim for:
Privacy-first design
- No advertising SDKs.
- No third-party tracking.
- No selling member information.
- No behavioural profiling.
- Minimal server logs with defined retention.
- Encrypted database storage and backups.
- E2EE for private messages.
- Transparent privacy policy.
- Member-controlled account deletion.
